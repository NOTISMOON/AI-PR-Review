# AI PR Review 平台 MySQL 数据库设计

> 技术基线：MySQL 8.x · InnoDB · utf8mb4 / utf8mb4_unicode_ci
> 企业规范要求：**不使用物理外键、建立合适索引（主键/二级/联合索引）、允许合理的冗余字段**。

---

## 〇、准入模型（重要）

本项目采用**多平台登录、但不做跨平台数据聚合**：

- GitHub、Gitee 都作为**登录身份来源**（登录页「使用 GitHub 登录 / 使用 Gitee 登录」两者独立可选）。
- **每个登录身份（provider + provider_user_id）= 一个独立的平台账号（user 一行）**，其仓库、PR、审查、Webhook、通知、设置全部挂在该身份下，互不合并。
- **没有**「注册一个统一平台账号再绑定多个 GitHub/Gitee」的流程，也**没有**跨平台数据聚合。
- 因此不需要独立的「平台账号 + 多平台绑定（1:N）」结构；`user` 直接就承载登录身份。
- 数据隔离策略：GitHub 数据与 Gitee 数据完全隔离，永不交叉聚合。

基于该模型，`repository`、`webhook_event` 等表保留 `platform` 作为**冗余列**（便于直接过滤/日志展示），但凭 `user.provider` 即可推导，属于冗余而非聚合依据。

边界策略（来自《后端重构方案》）：MySQL 只存业务数据与必要的镜像字段，Diff/文件内容等大对象按需从 GitHub API 获取并用 Redis 短期缓存。

---

## 一、设计原则

### 1.1 不建外键（Foreign Key）
- 一致性由**应用层（Prisma / 业务事务）**保证；物理层通过 `冗余字段 + 索引` 关联，避免外键的写入锁、级联成本与分库/迁移阻力。
- 关联都用「子表冗余父表主键列 + 二级索引」表现，查询走索引，不依赖 JOIN 的外键约束。

### 1.2 主键
- 统一 `BIGINT UNSIGNED AUTO_INCREMENT`（后续分库可换雪花/号段 ID，不影响索引设计）。
- 每个表必须有主键。

### 1.3 索引规范
- **唯一索引**：业务幂等/去重（`provider+provider_user_id`、`repository_id+pr_number`、`delivery_id` 等）。
- **联合索引**：按高频查询最左前缀建；等值列优先于范围/排序列。
- **二级索引**：单列高频筛选。
- 建索引克制（每表 3~6 个业务索引），避免写放大。

### 1.4 冗余字段
- 允许将高频展示/查询字段冗余到子表（`repository_id`、`pr_number`、`repo_full_name` 等），减少 JOIN。
- 冗余列标注 `（冗余）`，由写入方/同步任务维护一致性。

### 1.5 通用字段
- `created_at` = `DEFAULT CURRENT_TIMESTAMP`；`updated_at` = 同 + `ON UPDATE CURRENT_TIMESTAMP`。
- 软删除用 `status` 小数字段，不物理删业务主数据。

---

## 二、数据领域与关系（无外键）

```
user（一个登录身份，provider+provider_user_id 唯一）
  │
  ├─ 1:1 github_installation（GitHub 专用：App 安装）
  ├─ 1:N repository（owner 是其仓库）
  │      └─ 1:N pull_request ─ 1:N ai_review_job ─ 1:N review_issue
  ├─ 1:N review_task（creator/assignee）
  ├─ 1:N webhook_subscription 、 webhook_event
  ├─ 1:N notification
  └─ user_setting（KV）／ contribution_summary（每日聚合）
```

## 三、建表语句

### 3.1 账号域

```sql
-- 平台用户 = 一个登录身份（GitHub 或 Gitee）。（登录页双入口、设置页账号展示）
-- 多平台登录但数据不聚合：每一个(provider, provider_user_id) 是一条独立 user，无需注册与后续绑定。
CREATE TABLE `user` (
  `id`               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `provider`         VARCHAR(16)  NOT NULL COMMENT '登录身份来源: github | gitee',
  `provider_user_id` VARCHAR(64)  NOT NULL COMMENT '平台侧用户ID',
  `login`            VARCHAR(64)  NOT NULL COMMENT '平台用户名（冗余，展示用）',
  `display_name`     VARCHAR(128) DEFAULT NULL,
  `email`            VARCHAR(128) DEFAULT NULL,
  `avatar_url`       VARCHAR(512) DEFAULT NULL,
  `access_token_enc` VARCHAR(512) DEFAULT NULL COMMENT '访问令牌(加密)',
  `refresh_token_enc` VARCHAR(512) DEFAULT NULL COMMENT '刷新令牌(加密)',
  `token_expires_at` DATETIME DEFAULT NULL,
  `scopes`           VARCHAR(512) DEFAULT NULL COMMENT '授权范围',
  `role`             TINYINT NOT NULL DEFAULT 1 COMMENT '1=普通用户 2=管理员',
  `status`           TINYINT NOT NULL DEFAULT 1 COMMENT '1=正常 0=禁用',
  `last_login_at`    DATETIME DEFAULT NULL,
  `created_at`       DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`       DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_provider_uid` (`provider`, `provider_user_id`) COMMENT '登录身份唯一，幂等',
  UNIQUE KEY `uk_provider_login` (`provider`, `login`) COMMENT '防止同名登录重复建号',
  KEY `idx_status_created` (`status`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='平台用户（一个登录身份）';
```

```sql

  `repository_selection` VARCHAR(32)  DEFAULT 'selected' COMMENT 'all | selected',
  `status`               TINYINT NOT NULL DEFAULT 1 COMMENT '1=有效 0=已撤销',
  `created_at`           DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`           DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  UNIQUE KEY `uk_installation` (`installation_id`),

```


```sql

  `repository_id` BIGINT UNSIGNED NOT NULL COMMENT '冗余 repository.id',

  `pr_number`     INT UNSIGNED NOT NULL,
  `title`         VARCHAR(255) NOT NULL,
  `body`          MEDIUMTEXT,
  `author_login`  VARCHAR(64) NOT NULL,
  `state`         VARCHAR(16) NOT NULL DEFAULT 'open' COMMENT 'open | closed | merged',
  `is_draft`      TINYINT NOT NULL DEFAULT 0,
  `base_branch`   VARCHAR(128) DEFAULT NULL,
  `head_branch`   VARCHAR(128) DEFAULT NULL,
  `base_sha`      CHAR(40) DEFAULT NULL,
  `head_sha`      CHAR(40) DEFAULT NULL COMMENT '最新commit_sha，幂等/触发重审',
  `additions`     INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '冗余',
  `deletions`     INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '冗余',
  `changed_files` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '冗余',
  `merged_at`     DATETIME DEFAULT NULL,
  `closed_at`     DATETIME DEFAULT NULL,
  `html_url`      VARCHAR(512) DEFAULT NULL COMMENT '冗余',
  `created_at`    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_repo_number` (`repository_id`, `pr_number`),
  UNIQUE KEY `uk_repo_head_sha` (`repository_id`, `head_sha`) COMMENT '防同Commit重复入库',
  KEY `idx_owner_state` (`owner_id`, `state`, `updated_at`),
```

## 四、索引与冗余清单

| 表 | 唯一索引（幂等） | 联合索引 | 二级索引 | 冗余字段 |
|---|---|---|---|---|
| user | provider+provider_user_id, provider+login | status+created_at | - | login, display_name, avatar |
| github_installation | installation_id | - | user_id | account_login, account_type |
| repository | platform+provider_repo_id, owner+name | platform+auto_review | owner_id, last_synced_at | stars, forks, pending_pr_count, language, html_url |
| pull_request | repository_id+pr_number, repository_id+head_sha | owner_id+state+updated_at | author, created_at | owner_id, additions, deletions, changed_files |
| review_task | - | owner_id+status+created_at, assignee_id+status+created_at, status+created_at | pull_request_id | owner_id, pr_number, repo_full_name, pr_title |
| ai_review_job | pull_request_id+commit_sha | owner_id+status+created_at, status+created_at | repository_id+created_at, pull_request_id | owner_id, pr_number, 各类_count, summary |
| review_issue | - | owner_id+pull_request_id+created_at, file+line, kind+severity | job_id | owner_id, repository_id, pr_number |
| webhook_subscription | - | owner_id+platform+enabled | repository_id | owner_id |
| webhook_event | platform+delivery_id | event_name+created_at, queue_status+retry_count | repository_id | owner_id, platform, pr_number, action |
| notification | - | user_id+read_status+created_at, type+created_at | - | review_task_id, link |
| outbox_event | event_id | status+created_at | aggregate_type+aggregate_id | - |
| user_setting | user_id+setting_key | - | - | - |
| contribution_summary | user_id+stat_date | stat_date | - | - |

> 关键点：`owner_id / user_id` 是**数据隔离的第一道闸**——所有业务子表都冗余该列并建联合索引，保证「一个登录身份只能看到自己的数据」，天然规避跨平台越权。

## 六、说明与后续项

1. **登录即建号，无需注册与绑定**：登录后按 `(provider, provider_user_id)` 幂等创建 `user`；同一自然人用 GitHub 登录与用 Gitee 登录会得到**两个独立账号**，数据互不连通（符合"多平台登录、不聚合数据"）。
2. **数据隔离**：所有业务表的 `owner_id/user_id` 冗余列 + 联合索引，是强制隔离的手段；前端每次查询都以当前登录身份（`user.id`）为前缀条件。
3. **Docker/本地可运行**：DDL 可作为 migration 基线；若用 Prisma，改用 `@id @default(autoincrement())`（BIGINT）、补充 `@@index`/`@@unique` 与注释即可，无需外键关系绑定。
4. **大对象不入库**：PR Diff / Patch / 源码文件内容不落 MySQL，按需 GitHub API 获取 + Redis 短期缓存。
5. **无外键的一致性**：删除/级联由应用层事务（Prisma 事务 + Outbox）保证。
